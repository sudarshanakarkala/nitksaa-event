New diagnostics structure
- Developer Diagnostics is now a navigation-based diagnostic center.
- Main screen is an index/dashboard with Quick Actions and row-style diagnostic entries.
- Each diagnostic row includes:
  - Icon
  - Title
  - Short description
  - Status badge: OK, INFO, WARNING, ERROR, or N/A
  - Last run timestamp
  - Chevron navigation indicator
- Required dashboard categories are present:
  - Foundation Status
  - Logger Test
  - Theme Control
  - Firebase Token Test
  - Backend Auth Test
  - /auth/me Test
  - Event Users Test
  - Database Tables Test
  - Network Test
  - App Performance
  - Debug Tools
- Quick Actions section includes:
  - Run All Diagnostics
  - Export Diagnostic Report
  - Clear Cached Data

Detail pages
- Foundation Status detail shows app, environment, Firebase, Hive, theme, platform, router, logger, and auth status.
- Logger Test detail preserves debug/info/warning/error logger test buttons.
- Theme Control detail preserves the light/system/dark segmented control.
- Firebase Token Test detail preserves debug token capture and token-copy behavior. UI only shows a shortened token preview.
- Backend Auth Test detail preserves Firebase token backend exchange validation.
- /auth/me Test detail preserves backend JWT validation against /api/v1/auth/me.
- Event Users Test detail preserves event_users diagnostic table refresh behavior.
- Database Tables Test detail preserves database table list and row inspection behavior.
- Network Test detail adds safe backend health endpoint checking for /api/v1/health.
- App Performance detail provides runtime/platform diagnostics and DevTools guidance.
- Debug Tools detail provides report export and cached backend session cleanup.

Functionality preserved
- Firebase token capture remains debug-only.
- Backend Firebase login exchange remains pointed at /api/v1/auth/firebase.
- Backend JWT validation remains pointed at /api/v1/auth/me.
- event_users diagnostics remain pointed at /api/v1/dev/diagnostics/db/event_users.
- Database table diagnostics remain pointed at /api/v1/dev/diagnostics/db/tables and table-specific diagnostics endpoints.
- Existing logger test actions were preserved.
- Existing theme switching was preserved.
- Existing Developer Diagnostics entry link remains debug-only on LoginScreen.
- Developer route is now also registered only in debug builds.
- RouteGuards reject /developer outside debug builds.
