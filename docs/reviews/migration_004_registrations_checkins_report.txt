Risks
-----
- This migration depends on Migration 001, 002, and 003 having already created events, sessions, and event_users.
- registrations.firebase_uid requires a matching event_users row before a registration can be inserted.
- registrations enforces one registration per event and firebase_uid through UNIQUE (event_id, firebase_uid).
- The Product Owner schema uses qrtoken and checkin_id. Current backend/app Alpha code still uses qr_token and check_in_id naming, so API code must not be pointed at this schema until later migration work updates it intentionally.
- No check_in_attempts table is created in this migration because it is not part of the provided Product Owner schema.
