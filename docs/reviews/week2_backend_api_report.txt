Scope

APIs implemented

APIs intentionally not implemented

- Attendee management APIs are not part of Week 2.

DELETE endpoint status
- Runtime check: DELETE /api/v1/events/1 returned HTTP 405.
- Result: PASS. Hard delete is not implemented on the Week 2 event route.

Admin auth behavior
- Admin event endpoints depend on get_admin_user.
- In development, get_admin_user requires X-Dev-User: admin.
- Non-admin development users are rejected with admin_required.
- Dev auth is blocked outside APP_ENV=development.

Public API behavior
- Public list and detail routes require no authentication.
- Public route order places /events/public before /events/{event_id}.
- Public list supports period=upcoming|past|all, page, and per_page.
- Public detail only returns events with status='published'.
- Public responses include event display fields, registration_status, and registered_count.

Event status model
- Supported status transitions:
  draft -> published, cancelled
  published -> draft, cancelled, completed
  cancelled -> terminal
  completed -> terminal
- Publish validates required public fields before status transition.
- Unpublish is represented by published -> draft.
- Cancel records cancelled_at.

Validation rules
- title is required.
- start_datetime and end_datetime are required for create.
- end_datetime must be after start_datetime.
- Physical events require location_text.
- Virtual events require virtual_url internally.
- capacity must be positive when provided.
- Publish requires title, description, start_datetime, end_datetime, timezone, capacity, and location_text or virtual_url depending on event type.

Audit logging behavior
- create_event writes event_created.
- update_event writes event_updated.
- publish writes event_published.
- unpublish writes event_unpublished.
- cancel writes event_cancelled.
- Audit rows are internal and are not selected by public APIs.
