Root cause
- Not conclusively determined without a fresh Firebase ID token hitting the instrumented backend.
- Confirmed not an obvious backend settings/ADC project mismatch from local ADC diagnostics:
  backend Firebase project, ADC project, and ADC quota project all resolve to project-d22bed42-f302-4e23-8dc.
- Most likely remaining causes to confirm from TEMP DEBUG output:
  1. Token aud does not equal project-d22bed42-f302-4e23-8dc.
  2. Token iss does not equal https://securetoken.google.com/project-d22bed42-f302-4e23-8dc.
  3. Firebase Admin reports a certificate/network/token-format verification failure.
  4. The running server process has not reloaded the edited backend file before the fresh-token test.

Recommended fix
- Run the fresh-token curl against the currently running backend after confirming the server has reloaded backend/app/middleware/auth.py.
- Use the TEMP DEBUG console output to decide the fix:
  - If aud differs from project-d22bed42-f302-4e23-8dc, the app is generating a Firebase token for a different Firebase project; fix client/Firebase app configuration outside backend code.
  - If iss differs from https://securetoken.google.com/project-d22bed42-f302-4e23-8dc, the token is not from the expected Firebase project; fix client/Firebase app configuration outside backend code.
  - If DefaultCredentialsError appears, fix ADC on the backend host with gcloud auth application-default login or the existing ADC mechanism; do not switch to service-account JSON unless the project policy changes.
  - If CertificateFetchError appears, investigate backend network access to Google's public cert endpoints.
  - If the token is expired or revoked, request a fresh ID token from Firebase Auth immediately before POST /api/v1/auth/firebase.
- Remove all TEMP DEBUG logging from backend/app/middleware/auth.py after the real root cause is captured.
