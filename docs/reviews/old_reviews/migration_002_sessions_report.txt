Risks
-----
- This migration depends on Migration 001 having already created events(event_id).
- The Product Owner schema uses start_datetime and end_datetime. Current backend/app Alpha code still uses the older starts_at and ends_at naming, so API code must not be pointed at this schema until later migration work updates it intentionally.
- The sessions table intentionally does not include track_name, capacity, status, or updated_at.
- Applying the old Alpha migration and Product Owner migrations in the same database remains incompatible because both define event/session schemas differently.
