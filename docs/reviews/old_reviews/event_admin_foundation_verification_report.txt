CORS FIX — 2026-06-03
================================================================================

Issue reported:
  Admin portal login page showed:
  "Network error: cannot reach backend at http://localhost:8000. Is it running?"
  even though the backend was healthy.

Root cause:
  backend/app/main.py was missing CORSMiddleware.
  curl works because it ignores CORS. The browser enforces it.
  fetch() from http://localhost:5173 → http://localhost:8000 was blocked.
  The browser threw TypeError: Failed to fetch, which apiClient.js caught
  and reported as "Network error: cannot reach backend".

Key finding:
  backend/app/config.py already had:
    allowed_origins: str = Field("http://localhost:5173", alias="ALLOWED_ORIGINS")
    origins_list property (parses comma-separated origins)
  The config was fully designed for CORS — it was simply never wired up.

Fix applied (backend/app/main.py):
  Added: from fastapi.middleware.cors import CORSMiddleware
  Added: app.add_middleware(
             CORSMiddleware,
             allow_origins=settings.origins_list,
             allow_credentials=True,
             allow_methods=["*"],
             allow_headers=["*"],
         )

Files changed:
  backend/app/main.py  — 1 import + 8 lines added
  No schema, migration, database, or Flutter changes.

Post-fix verification:
  OPTIONS /health   (Origin: localhost:5173) → HTTP 200 + access-control-allow-origin: http://localhost:5173  ✓
  OPTIONS /auth/firebase (Origin: localhost:5173) → HTTP 200  ✓
  OPTIONS /auth/me  (Origin: localhost:5173) → HTTP 200  ✓
  GET /health with unknown origin → no Access-Control-Allow-Origin header (correctly blocked)  ✓

Adding more origins (e.g. production):
  In backend/.env add:
  ALLOWED_ORIGINS=http://localhost:5173,https://admin.nitksaa.org

================================================================================
KNOWN LIMITATIONS (Week 1)
================================================================================

1. No admin role check on the frontend.
   The backend returns user_type ("alumni", "staff", "admin"). The frontend
   does not yet enforce admin-only access. Any authenticated user can see the
   admin portal. Add a check in RequireAuth or a new RequireAdmin component.

2. Token expiry not handled.
   If the backend JWT expires mid-session, the next API call that returns 401
   will trigger a hard redirect (window.location.replace) to /login. This is
   functional but not graceful. Implement token refresh when the backend
   supports it.

3. No error boundary.
   Unhandled React render errors will show a blank screen. Add a top-level
   ErrorBoundary component before production.

4. Mobile layout not implemented.
   The sidebar is fixed-width (240px). On small screens the layout overflows.
   Add a hamburger menu and responsive sidebar for mobile.

5. Email/password sign-in requires the user to exist in Firebase Auth console.
   No self-registration flow is implemented. Admin users must be created manually.

6. Audit vulnerabilities in dev dependencies.
   12 vulnerabilities in transitive deps (Vite, ESLint, Rollup). These are
   dev-only and do not affect the production build output. Review before shipping.
