SECTION 1 — BUG FOUND AND FIXED
==============================================================================

Bug: JSONB metadata field caused HTTP 500 on all registration and check-in
     response routes.

Root Cause:
  asyncpg 0.29 returns JSONB columns as raw Python strings (e.g., '{}')
  not as Python dicts. FastAPI's Pydantic v2 response validation rejects a
  str value for a field declared as Dict[str, Any], raising:
    ResponseValidationError: Input should be a valid dictionary

Attempted first fix (rejected):
  Registered a JSON/JSONB type codec via asyncpg pool `init` callback.
  This BROKE the INSERT path: the codec's json.dumps encoder double-encoded
  the already-stringified metadata, storing '"{}"' (JSON string) instead of
  '{}' (JSON object) in PostgreSQL.

Final fix (minimal, correct):
  Reverted the codec registration.
  Added a Pydantic field_validator on the `metadata` field in all three
  response schemas. The validator coerces str → json.loads(v) → dict.

Files modified:
  1. backend/app/schemas/registrations.py
     - Added import: json, field_validator
     - Added helper: _parse_jsonb(v)
     - Added @field_validator("metadata", mode="before") on RegistrationResponse

  2. backend/app/schemas/checkins.py
     - Added import: json, field_validator
     - Added helper: _parse_jsonb(v)
     - Added @field_validator("metadata", mode="before") on CheckInResponse

  3. backend/app/database.py
     - Reverted JSONB codec registration (net: restored to original state)
